T3 Code fork: how updates arrive

Who does what, what is manual, what is automatic, and which versions come out.

The four actors

pingdotggUpstreampingdotgg/t3code. The maintainers publish the stables (v0.1.6, v0.1.7...). You never touch it.
localYour MacThe checkout on the fork branch, the self-signed certificate and fork/release.sh. The signed build happens here.
essedevYour fork on GitHubessedev/t3code. Its Releases are the "store" your app downloads updates from.
installedYour appT3 Code installed in /Applications. It checks the fork's Releases, not the official ones.

Case 1: upstream publishes a new stable

You only want to keep up, with no new changes of your own

Upstream
Publishes v0.1.7.
→
You, 2 commands
git fetch upstream --tags
git rebase v0.1.7
Your changes are reapplied on top of 0.1.7. Conflicts only if upstream changed the same files.
→
You, 1 command
fork/release.sh
Signed build of 0.1.7, published to essedev/t3code. About 5 minutes.
→
Automatic
The app sees 0.1.7, downloads it and restarts updated.

The fork does not follow upstream by itself: until you run the rebase and the release, your app stays where it is. A GitHub Action could take this over later, when the rebase passes without conflicts.

Case 2: you make a change between two stables

Example: you add a feature while upstream is still on 0.1.7

You
Work on the fork branch and commit.
→
You, 1 command
fork/release.sh
It sees the fork's 0.1.7 is already out and releases a prerelease of the next patch: 0.1.8-fork.1.
→
Automatic
The app updates to 0.1.8-fork.1.

The suffix exists because the updater offers only versions higher than the installed one. Semver orders 0.1.7 < 0.1.8-fork.1 < 0.1.8-fork.2 < 0.1.8, so when upstream publishes 0.1.8 your app still receives it.

What works with each kind of version

Matching upstream (0.1.7) With suffix (0.1.8-fork.1)
Normal app use, threads, providers, Connect Yes Yes
In-app update from your fork Yes Yes
Background service, SSH environments, t3 update Yes No, until the next stable. They download the CLI runtime from upstream by version number, and 0.1.8-fork.1 does not exist there.

Manual or automatic

Step Who When
Self-signed certificate and trust manual Once, already done.
Creating the fork essedev/t3code manual Once, already done.
First install of the fork in place of Nightly manual Once: drag the DMG to Applications.
Rebase on a new stable manual For each upstream stable you want to take.
fork/release.sh manual After a rebase or a change of yours.
App download, install and restart automatic Always, from the app.
